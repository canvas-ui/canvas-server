Workspace/SynapsD tree refactor (implemented 2026-07-12): every workspace pre-creates THREE trees — `context` (context), `directory` (directory), `backends` (directory, `settings: { linkContextRoot: false, protected: true }`). Backend mirrors live in the backends tree at `/<driver>/<address>/<subpath>` (e.g. `/imap/user@x/inbox`, `/file/workspace:home/Projects`) — the `/.backends` subtree and `indexIncoming`/`incomingPathMode`/`includeBackends`/`shouldExcludeBackends` are all gone (supersedes [[project-incoming-lock-semantics]]).

Key mechanics:
- synapsd tree meta has a generic `settings` bag; `linkContextRoot:false` stops the auto context-root tick for directory-only inserts (replaces the `.backends` path heuristic). synapsd stays backend-agnostic.
- `db.listTreeDocuments(tree, {path, linked})` = bitmap query for docs on a backend linked/not-linked into any other tree; REST `GET /workspaces/:id/backends/:driver/:address/documents?linked=false` = safe-to-purge candidates; webui "Unfiled only" chip.
- `DirectoryTree.removePath` now cleans the synapse reverse index (was a latent corruption bug) and accepts `{ignoreLocks}`; bitmap-key prefixes must be normalized (lowercase) when matching synapse keys — ULID tree/node ids are uppercase (fixed `listDocumentTreePaths` et al.).
- Workspace write API: tree-qualified selectors pass through as objects (`#buildWriteSpec`) — the `ctx:`/`dir:` paths grammar only addresses DEFAULT trees. ALL backend-ingest puts must pass `context: null` (imap, stored-index, graph, chat) or docs leak into the context root.
- Migration: one-shot on start — drop legacy `/.backends` from directory tree (`ignoreLocks`), then file-backend `resyncInBackground()` + imap metadata-based re-file (feature bitmap `data/backend/imap/<account>` + `doc.data.folder`, no network). Guard = `pathExists('/.backends')`.
- Sync exclusions: `DEFAULT_SYNC_EXCLUSIONS` (constants.js) ∪ per-backend `exclude[]` (dataBackends config, PATCH via /data-backends), applied via one picomatch matcher shared by chokidar watch + list()/scan(); patterns ending `/**` also prune the dir itself. stored drivers expose `capabilities.canEnumerate`.
- Blob cascade: plain `Workspace.delete/deleteMany` now deletes cacache blobs for docs whose EVERY location is on a `managed:true` backend (workspace:data) via `storedIndex.deleteStoredUrl`.
- webui: 4 icon tabs (context, layers, directory, backends); root-click bug fixed in `url-params.ts` (parser accepts `/trees/:tree` without `/path`); `treeTypeForName()` helper maps backends→directory; readOnly toggle + exclusions editor in Settings > Data.
- workspace:data + stored.cache are structural/always-on: `Workspace.setDataBackendConfig` rejects `enabled:false` and any `readOnly` patch for them (readOnly is a workspace:home/samba concern only); settings UI shows an "always on" badge and hides read-only for managed stores.
- Thumbnails/internal cache: Stored's internal cache (remote-resource copies + thumbnails) is pointed at {WORKSPACE_ROOT}/cache via `cache: { path }` in the Stored config — SAME dir as the stored.cache settings entry (legacy .stored/cache dirs are NOT auto-cleaned — user removes manually; content is regenerable). stored.cache is internal-only: no sync-exclusion editor in settings. Thumbs keyed `thumb:<primaryChecksum>:<edge>`. The "stale thumbnail on recycled doc id" bug was the HTTP layer: /documents/:id/thumbnail had max-age=86400 while doc ids are GC'd+reused — fixed with content-addressed ETag ("<checksum>:<size>") + Cache-Control no-cache (cheap 304 revalidation) on both authed and /pub routes. `purgeThumbnails(docs|checksums)` runs on delete/destroy/reconcile paths; `clearThumbnailCache()` + `DELETE /workspaces/:id/thumbnails` wipes thumb:* (button on Settings > Data stored.cache card).
- Post-refactor fixes (2026-07-12): (1) duplicate-"context"-tree bug = concurrent Workspace.start() race — WebDAV auto-starts per request, isActive flips only at the END of start, so parallel PROPFINDs each re-ran start against a fresh #db with an unloaded tree registry → duplicate trees; FIXED by serializing start() behind an in-flight #startPromise (getWorkspace caches instances with no await before set, so per-instance serialization suffices). (2) #assertTreeNotReserved now guards by resolved IDENTITY (db.getTree(reservedName)?.id === tree.id) + settings.protected, not by name — stray duplicates carrying a reserved name are deletable by id via DELETE /trees/:id. (3) backends/directory-tree SEARCH regression: directory scoping was node-exact (tree.find), docs tick only leaf nodes → search at ancestor folders matched nothing; FIXED with `recursive: true` on directory selectors (spec.js treeEntry → #buildPathsBitmap → #buildDirectorySelectorBitmap uses findRecursive), set by documents.js GET route whenever text queries are present; folder LISTINGS stay node-exact.
- Disk usage (on-demand only, never automatic — slow tree walks): `GET /workspaces/:id/backends/:driver/:address/usage` (per local backend, cached on backend status as `usage`) and `GET /workspaces/:id/usage` (whole workspace root + per-top-level-dir breakdown, for future export/sync). Uses `get-folder-size` (root dep) — hardlink/inode-aware (stored commit() hardlinks) and cross-platform; NOTE the npm `diskusage` module measures VOLUME free/total, not folder sizes. UI: size button on Settings > Data cards + "Disk usage" section on Settings > General.
