Widgets self-register via `widget-registry.ts` on import (`widgets/index.ts`); each gets `canvas.fetchDocuments(opts)` injected (never calls services directly) so it works in-app and on public canvases.

**Filter composition model (verified)**: 3 layers AND-compose server-side in `Workspace.#composeCanvasQuerySpec` → synapsd `#resolveParsed`: path/context ∩ (canvas querySpec.features ∪ request allOf) ∩ (canvas querySpec.filters ∪ request filters). Widget `allOf` is UNIONED into the allOf bucket then AND-ed — additive, never replaces canvas filters. So a widget safety-checking its own bitmap on top is compliant. BUT only `querySpec` is server-enforced; `metadata.toolbox` is client-side convenience the backend never reads.
**Timeline scope now server-enforced (gap CLOSED)**: web toolbox `saveFilters` (toolbox-context.tsx canvas branch) now sets `querySpec.filters: buildDatetimeFilters(filters.timeline)` (was `[]`), reusing the same `t:<name>:<spec>` token builder (types/workspace.ts) the folder view already lists with. So a per-canvas saved timeline scope AND-composes server-side and is inherited by widgets AND public shares (pub/canvases.js merges querySpec.filters too). `metadata.toolbox` still written for UI round-trip only. Token grammar: `[+/!]t:<name>:<spec>`, spec = CRUD keyword (today/lastWeek… crud:* only, resolved live at query time), `start..end` range, or single value; parser synapsd utils/filters.js. Timeline SORT (sortBy/order) is separate and already worked. Canvas = frozen server-composed view; widgets play within it.

**Canvas sort persistence (querySpec.sort)**: canvas querySpec gained a `sort: {sortBy, order}|null` field (was only features/filters/query). Backend: `Canvas.normalizeQuerySpec` stores it; `Workspace.#composeCanvasForScope` injects it as spec.sortBy/order when the CALLER didn't send sortBy (request wins, canvas = default view order). So public shares (payload built via `workspace.list(listSpec)` whose `context: selector` resolves the canvas leaf) come out pre-sorted, and widgets/folder inherit it. Frontend: `ToolboxFilters.sort` (DEFAULT crud:created desc), extracted from metadata.toolbox, saved into querySpec.sort by toolbox `saveFilters` + page save-as-canvas; `setSort` action; content-area sort UI = `TimelineSortControl` in DocumentList toolbar via new `serverSort`/`onServerSortChange` props (threaded page→DefaultCanvas→DocumentList); page fetch passes sortBy/order (in tbFiltersKey → refetch). Also: DocumentList table "Type" column now client-sortable (`type` accessor = contentType||schema); MetadataTab shows Photo section (EXIF/geo/dimensions) from `document.metadata.{exif,geo,dimensions}`.

**Widget sort → canvas querySpec.sort (bake-in)**: widget sort controls now edit a CANVAS-LEVEL sort via `WidgetCanvasContext.canvasSort`/`setCanvasSort` (not widget-local). **Public/read-only shares gotcha**: `publicFetchDocuments` (pages/pub/canvas.tsx) is a preloaded snapshot that IGNORES fetch opts (sort/search/paging are inert). `lib/api.ts` bounces any 401 to /login. So a widget calling an AUTHED endpoint on a share (e.g. `listWorkspaceTimelines` behind the sort control) → 401 → login redirect, breaking unauth access. Fix pattern: gate authed/interactive toolbars on `canvas.readOnly` — Gallery/Mosaic hide `ImageGridToolbar`, Documents hides its sort bar + nulls `onBackendSearch`/`onRemoveBackendQuery` when readOnly. Share-aware thumbnail/blob hooks are fine on shares. Always check: does a new widget control hit an authed route? If so, guard it behind `!canvas.readOnly`.

**Search security decision**: canvas-driven search is safe because only the free-text term (`q`) is user-controlled; scope (path/tree/filters/sort) is structured params baked server-side and always intersected with the token scope. Never expose `scope=workspace` to canvas search (bypasses path bucket); clamp limit; single term (no unbounded `q` stacking). See [[feedback_url_design]].
